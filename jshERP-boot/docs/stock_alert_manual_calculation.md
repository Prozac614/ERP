# 库存预警手动计算功能说明

## 📋 **功能概述**

将库存预警状态的计算逻辑从自动计算改为手动触发，解决了状态被意外覆盖的问题。

### **设计原理**
- ✅ **查询时**：直接从数据库读取 `stock_alert_status` 字段，不进行任何计算
- ✅ **手动触发**：点击"库存预警校验"按钮时，批量重新计算所有商品的状态
- ✅ **完全覆盖**：校验结果直接覆盖所有原有状态，包括忽略风险状态

## 🎯 **主要改进**

### **1. 后端改进**
- **移除自动计算**：`getMaterialStockWithDailyOutOptimized` 接口不再自动计算状态
- **新增批量校验接口**：`/depotItem/calculateAllStockAlertStatus`
- **完全覆盖机制**：校验时所有商品状态都会被重新计算并覆盖

### **2. 前端改进**
- **新增操作按钮**：在页面顶部添加"库存预警校验"按钮
- **确认对话框**：防止误操作，提醒用户操作可能耗时较长
- **加载状态**：显示计算进度，防止重复点击

## 🔧 **使用方法**

### **日常使用**
1. **查看状态**：打开库存管理页面，直接查看商品的库存预警状态
2. **忽略风险**：对于不需要关注的商品，点击"忽略风险"
3. **关注风险**：对于需要重新关注的商品，点击"关注风险"

### **批量更新状态**
1. **点击按钮**：在页面顶部点击"库存预警校验"按钮
2. **确认操作**：在弹出的确认对话框中点击"确认"
3. **等待完成**：系统会显示计算进度，完成后自动刷新页面

## 📊 **状态说明**

### **库存预警状态**
- 🟢 **NO_RISK**：无风险（当前库存 ≥ 六个月销量）
- 🔴 **STOCK_ALERT**：库存告急（当前库存 < 六个月销量）
- 🟡 **RISK_IGNORED**：忽略风险（用户手动设置，不参与自动计算）

### **计算逻辑**
```
如果 当前库存 >= 过去6个月销量：
    状态 = NO_RISK（无风险）
否则：
    状态 = STOCK_ALERT（库存告急）

特殊情况：
- RISK_IGNORED 状态的商品在批量计算时会被跳过
- 新商品默认状态为 NO_RISK
```

## 🔍 **技术实现**

### **后端接口**

#### **1. 查询接口（已修改）**
```
GET /depotItem/getMaterialStockWithDailyOutOptimized
```
- **功能**：直接读取数据库状态，不进行计算
- **返回**：包含 `stockAlertStatus` 字段的商品列表

#### **2. 批量计算接口（新增）**
```
POST /depotItem/calculateAllStockAlertStatus
```
- **功能**：批量计算所有商品的库存预警状态
- **返回**：计算结果统计信息

#### **3. 忽略/关注风险接口（已有）**
```
POST /depotItem/ignoreStockRisk
POST /depotItem/focusStockRisk
```
- **功能**：单个商品的状态操作

## 📈 **性能优化**

### **查询性能**
- ✅ **无计算开销**：查询时不进行任何计算，响应速度更快
- ✅ **数据库索引**：为 `stock_alert_status` 字段创建了索引
- ✅ **缓存友好**：状态稳定，适合缓存

### **批量计算性能**
- ✅ **分批处理**：每100个商品输出一次进度日志
- ✅ **跳过保护**：忽略风险的商品直接跳过，减少计算量
- ✅ **异步处理**：不阻塞其他操作

## 🛡️ **数据安全**

### **状态保护**
- ✅ **忽略风险保护**：`RISK_IGNORED` 状态不会被批量计算覆盖
- ✅ **操作确认**：批量计算需要用户确认
- ✅ **日志记录**：所有操作都有详细的日志记录

### **错误处理**
- ✅ **异常捕获**：计算失败不会影响系统稳定性
- ✅ **回滚机制**：单个商品计算失败不影响其他商品
- ✅ **用户反馈**：操作结果会及时反馈给用户

## 📝 **使用建议**

### **最佳实践**
1. **定期校验**：建议每周或每月执行一次库存预警校验
2. **合理忽略**：对于长期库存商品，可以设置为忽略风险
3. **及时关注**：对于重要商品，及时从忽略状态改为关注状态

### **注意事项**
1. **计算耗时**：商品数量较多时，批量计算可能需要较长时间
2. **网络稳定**：确保网络连接稳定，避免计算中断
3. **权限控制**：建议只有管理员才能执行批量计算操作

## 🆘 **故障排除**

### **常见问题**
1. **按钮无响应**：检查网络连接和后端服务状态
2. **计算失败**：查看后端日志，检查数据库连接
3. **状态不更新**：刷新页面或清除浏览器缓存

### **日志查看**
```bash
# 查看批量计算日志
tail -f application.log | grep -i "批量计算库存告急状态"

# 查看状态更新日志
tail -f application.log | grep -i "更新商品.*库存告急状态"
```
